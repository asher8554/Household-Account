# Notion 카테고리 백업 보존 계획

## 목표

현재 브라우저에서 지정한 거래 카테고리를 이름까지 식별하고 복구할 수 있도록 Notion 백업에 카테고리 정의를 함께 보존한다.

## 범위와 결정

- 기존 createBackupData 및 두 호출 경로(Notion 기록, 현재 PC 기록 push)는 이미 categories와 categoryId를 전송한다. Worker 변환과 정리 로직을 수정한다.
- 카테고리 행에는 ID, 이름, 구분, 색상, 활성/기본 여부, 순서와 생성/수정 시각을 저장한다. 거래 행에는 categoryId와 categoryName을 함께 저장한다.
- 기존 카테고리 행을 삭제하지 않고 recordId 또는 이전 ID 제목으로 매칭해 갱신한다. 중복 행 및 과거 요약 정리 동작은 유지한다.
- 화면 구조 및 스타일은 수정하지 않는다. 백업 키·사용자 브라우저 저장소·공개 공유 데이터는 변경하지 않는다.
- 현재 브라우저 백업의 실제 실행은 해당 브라우저의 데이터 및 백업 키가 필요하다. 테스트 데이터로 운영 금융 행을 생성하지 않는다.

## 검증

1. 변환 테스트로 사용자 카테고리 정의와 거래 이름 매핑, 비활성/미사용 카테고리 및 기존 multi_select 호환성을 확인한다.
2. Worker 요청 테스트로 카테고리 보존/갱신, 중복 정리, 20건 배치 진행과 재실행 종료를 확인한다.
3. 전체 Playwright 테스트 및 앱 빌드를 실행하고 Worker 배포 가능 여부를 확인한다.
