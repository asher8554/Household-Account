# Notion 백업 완료 후 진행률·글래스 UI 개선

## 진행 순서와 완료 조건

1. 현재 백업부터 완료한다. 사용자 요청에 따라 백업 실행 중 UI 변경·페이지 새로고침·프런트 배포는 하지 않는다.
2. 실패한 경우 실제 오류 로그를 확인하고 백업 경로만 수정한다. 브라우저의 데이터·키와 Notion 기존 거래는 보존한다.
3. 백업 완료와 최근 거래 반영을 확인한 뒤 진행률 막대와 공통 유리 스타일을 조정한다.

## 확인된 오류

- 운영 페이지의 Failed to fetch를 재현했다. wrangler tail에서 POST /backups가 Exceeded CPU Limit이며 Worker exceeded CPU time limit 예외를 확인했다.
- 기존 Worker는 매 batch 전체 payload 파싱·모든 Notion 행 조회·전체 행 변환을 반복한다. 20건 단위 쓰기를 하더라도 이 읽기 비용을 반복한다.
- 먼저 현재 처리할 행만 조회하고 cursor를 실제 처리 위치로 사용하는 최소 수정으로 CPU 비용을 줄인다. 실제 운영 재시도로 확인한 뒤 필요할 때만 요청 payload도 축소한다.

## UI 방향

- 사용자는 다크 모드·현재 색상 유지, 투명감·배경 흐림·빛 반사 강화를 선택했다.
- 시각적 방향은 기존 녹색 다크 유리를 더 투명하게 표현하되 텍스트 대비를 보존하는 것이다. 패널·입력 배경의 투명도, 배경 디테일, 빛 반사와 경계·그림자를 함께 조정한다.
- 내용 순서는 상태·퍼센트, 진행률 막대, 처리 건수와 생성/업데이트/정리 수다. 기존 버튼과 기능·순서는 유지한다.
- 동작은 batch 응답에 따른 부드러운 막대 갱신, 처음 응답 전 대기, 완료 100%, 오류 시 마지막 진행 상태 유지다. reduced-motion 환경에서는 움직임을 줄인다. ARIA progressbar로 상태를 읽을 수 있게 한다.
- Notion 기록과 현재 기록 업데이트의 Notion 단계에서 같은 진행 UI를 사용한다. 새 의존성은 추가하지 않는다.

## 검증

- cursor·중복 방지·재시도·청크 조회 테스트 및 실제 Notion 백업 완료와 최근 거래 확인.
- 진행률 0·중간·완료·오류·0건 테스트, 앱 빌드, 데스크톱/모바일과 키보드 포커스 확인.
- 실제 반투명·배경 블러, 다크 모드, 로드된 Pretendard, 대비·잘림을 화면 캡처로 확인하고 마지막 수정 후 배포 화면을 다시 확인한다.
