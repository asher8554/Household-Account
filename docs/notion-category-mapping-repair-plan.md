# Notion 거래 카테고리 ID 매핑 정정

## 문제와 근거

- 사용자가 보낸 표는 recordType=category인 참조 행을 거래와 함께 표시하고 있다. 이 행들의 금액·날짜·categoryId는 비어 있어 거래가 잘못 생성된 것처럼 보인다.
- 사이트의 현재 공유본은 카테고리 40개·거래 2506건이며 모든 categoryId가 정의된 ID다. Notion 전체 2391행(카테고리 41, 거래 2350)을 읽어 대조했다.
- 동일 recordId가 사이트에도 있는 거래 2284건 중 107건의 categoryId가 서로 다르다. 이름이 비었거나 매핑과 다른 거래는 총 1973건이다. 사이트에 없는 기존 Notion 거래 66건은 삭제하거나 임의 재분류하지 않는다.

## 수정

1. 동일 거래 ID 107건에 한해 사이트의 현재 categoryId를 적용한다. 변경 전후 ID와 이름은 저장소 밖 감사 파일로 남긴다. 금액·날짜·메모는 수정하지 않는다.
2. Notion 기본 수식 속성 `카테고리`를 사용해 categoryId와 40개 정의를 정확히 매핑한다. 현재의 잘못되거나 누락된 categoryName 텍스트에 의존하지 않는다. 기존 속성은 삭제하지 않는다.
3. Worker는 백업에 포함된 카테고리 정의로 수식 매핑을 갱신한다. 이름을 변경해도 거래마다 수천 번 재기입할 필요가 없게 한다.
4. 사용자가 보낸 표는 거래만 보이도록 필터하고 categoryId 옆에 카테고리 이름을 표시한다. 참조 행은 삭제하지 않는다.

## 검증

- 정확한 ID 비교, 같은 이름의 다른 ID, 이름 변경·따옴표·역슬래시 수식 인코딩을 테스트한다.
- 테스트·앱 빌드·Worker 타입 검사 뒤 배포한다.
- 변경한 거래 107건을 다시 조회해 ID를 대조하고, 전체 거래의 수식 결과와 현재 ID 매핑을 비교한다. 원본 거래의 금액·날짜·메모 보존도 확인한다.
- 실제 Notion 표에서 이름 연결 및 거래만 표시되는 결과를 확인한다. 추가 UI 스타일은 만들지 않는다.
